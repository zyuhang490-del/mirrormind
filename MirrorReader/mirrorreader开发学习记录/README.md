**学习阶段一 ≠ 产品开发阶段 1。** 现有程序支持翻页，但学习者是否理解仍待确认。AI 写过、程序能运行、看完教程，都不能单独作为“已掌握”的证据。

暂不创建大量阶段目录、知识库或评分表。有新的实际学习轮次，再创建“第二次建议情况 / 第二次完成情况”；同一任务未完成时，继续原反馈，不为换了一次对话就新增一套计划。只有任务或验收标准需要实质调整时，才记录新建议及调整原因。

小练习需要写代码时，再在当前阶段建立 `练习/`，使用公开示例数据，不直接改主程序，也不复制私人阅读材料。

## 4. 每次怎样继续

1. **定位**：读本 README、当前建议和最近执行反馈。
2. **复述**：用一句话确认“现在做哪个任务、上次停在哪”。
3. **行动**：只做一个最小练习或一个明确问题。
4. **核对**：查看实际输出、代码或自己的解释，不凭感觉勾完成。
5. **续接**：简记“做了什么／卡在哪里／下一步第一动作”，更新当前状态。

建议下一次对话直接说：

> 请先读取 MirrorReader/mirrorreader开发学习记录/README.md，再读取当前建议和执行反馈。沿用既有路线，从当前任务继续，先确认我的实际完成情况，不重新制定整体计划，不替我直接完成练习。

这些文件提供可恢复上下文，不等于所有新对话会自动读取它们；换任务或换会话时，主动指定这个入口。此处不设置定时提醒或后台自动跟进。

## 5. 协作与验收约定

- 优先让学习者尝试，再给提示、最小例子和解释；不一次交付整套新功能。
- 区分“看过 / 在提示下完成 / 能解释 / 能独立修改”，不制造虚假熟练度。
- 卡住时把任务再拆小；已经能解释并独立完成的内容可以通过验收跳过，不强制从头学。
- 每次反馈三句话也可以，不要求填写长报告。
- 改学习建议只依据实际反馈；不要因看到新工具或新项目就重排全程。
- 不必补齐全部基础才能开发：只补下一个具体改动所需的知识。
- 正式修改项目功能时，再同步项目侧记录；单纯学习不计作功能进展。
- C++ 继续承担专业基础学习，不为 MirrorReader 重写语言，也不在本目录另建一套 C++ 学习体系。
