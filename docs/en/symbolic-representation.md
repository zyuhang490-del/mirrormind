# Foundational Question 2: How Can Symbolic Systems Participate in Self-Structuring Without Fully Representing a Person?

[English index](README.md) | Chinese source (local Chinese draft: `Mirrormind底层元问题集/元问题2：符号系统如何在不可完全表示人的前提下参与自结构.md`; not included in this commit)

Status: initial synthesis, open to further challenge and validation. Created October 7, 2026. English edition: October 27, 2026.

The source uses “the real” for what a current symbolic system cannot adequately mediate or accommodate. It does not identify this usage directly with a particular philosopher's strict definition.

## 1. Central question

MirrorMind seeks representations of a person in context that can be recorded, stored, read, processed, compiled, communicated, interacted with, and edited. It would use these representations to generate temporary executable structures aligned with intention.

Yet a representation is not the person. Observation, recording, classification, interpretation, and compilation omit, compress, or change what they address.

> If a person's state cannot be fully represented symbolically, how can MirrorMind act and learn from state data without mistaking a provisional model for the person's real essence?

The problem has three dimensions:

1. **Epistemological:** what can the system know about a person, and what must it acknowledge it does not know?
2. **Ontological:** is there a stable true state waiting to be discovered, or are states also formed through relations and action?
3. **Practical:** how can the system act under uncertainty without removing the person's ability to revise, change, or restart in the name of efficiency?

## 2. How the problem arises

~~~text
Self-structuring requires an account of the person and environment
    → human states must become machine-operable representations
    → those representations generate temporary executable structures
    → outcomes and feedback provide learning signals
    → generation gradually adapts to a particular person
    → symbolic representations still cannot equal actual human state
    → representation, interpretation, and compilation leave remainder
    → anomalies expose model failure
    → reverse state identification revisits states, relations, and categories
~~~

Self-structuring therefore operates with a persistent representational gap. It does not begin after a complete user model has been acquired.

## 3. Four distinctions that must remain

~~~text
Actual human state
≠ raw observations and event data
≠ the system's state interpretation
≠ a program structure generated from that interpretation
~~~

### Actual human state

Includes body, emotion, cognition, history, relationships, environment, and possibilities not yet formed. The present system cannot capture it in full.

### Raw observations and event data

Expressions, file operations, page switches, project progress, and explicit feedback are partial traces of actual state.

### System interpretations

A hypothesis such as “the user may need a project map” is provisional. It requires sources, scope, confidence, alternatives, and user corrections.

### Generated program structures

Information presentation, tool composition, workflows, and interactions change based on the interpretation. Each structure is a revocable practical hypothesis, rather than a final definition of the person.

Conflating these layers lets “what I recorded” or “how I interpreted it” silently become “what this person is.”

## 4. Positions developed in the discussion

### 4.1 Self-structuring is learnable co-adaptation

It learns from earlier human–environment states and feedback how to organize information, tools, interfaces, and actions for a person's current intention. It goes beyond one dynamic tool invocation.

### 4.2 The person is the intention-end

The person determines value boundaries, purposes, and revision rights. The system can learn methods, but cannot promote predictions, efficiency measures, or historical models into the person's ends.

### 4.3 Descriptive remainder is structural

Symbolic mediation is always incomplete. The system should describe:

- Information it has not observed.
- Experience its fields cannot express.
- Behavior with multiple plausible explanations.
- Assumptions behind the current structure.
- Ways outcomes diverged from expectations.

Remainder may reflect change, new intention, contradiction, and creativity, as well as technical error.

### 4.4 Anomalies open reverse state identification

Neither discard anomalies immediately as noise nor romanticize them as revelations of essence. First consider whether the model has failed, then review states, relationships, environmental conditions, and categories.

### 4.5 Self-structuring forms through environmental coupling

Hardware, storage, files, programs, compilers, CLI, APIs, interfaces, and permissions provide bottom-up capabilities. Intention and boundaries provide top-down constraints. Protocols and feedback connect the two into temporary executable structures.

## 5. Six unresolved tensions

### 5.1 Representation is necessary, but can totalize the person

Without representation, collaboration across time is difficult. Richer representation can also confine a person within a profile built from the past.

> How can a model be useful while remaining open to the person exceeding it?

### 5.2 Adapting can become fixing the user in place

Frequent behavior can reflect inertia, avoidance, or a temporary phase. Adapting to it does not necessarily advance long-term intention.

Allow history to expire, sudden change, experiments inconsistent with earlier patterns, and requests to suspend personalization or restart.

### 5.3 Anomalies can be insightful, but can also be romanticized

An anomaly may reveal a new state or a deeper relationship, or simply bad records, chance, or environmental change.

~~~text
Anomaly ≠ essence
Anomaly = a reason to reopen interpretation
~~~

### 5.4 Reducing effort must preserve necessary friction

Deletion, payment, public publication, and changes of long-term direction require confirmation and reflection. Reduce unnecessary translation effort rather than eliminating all resistance.

### 5.5 Emergent structures require stable protocols

Temporary structures can vary. Identity, permissions, provenance, logs, rollback, confirmation, and revision rights must remain stable, or emergence becomes unverifiable and unaccountable.

### 5.6 Identifying a state can help produce it

Presenting and intervening in a user's state affects that user. The system enters the coupled relation rather than measuring passively from outside.

> Was an identified state already present, or did identification and interaction help form it?

## 6. Adversarial examination of the current position

### Challenge 1: is descriptive remainder just statistical error?

If larger models, richer sensing, and more data can absorb all remainder, perhaps it is only a temporary technical limitation.

**Provisional response:** some remainder is technical, but we cannot assume all of it is eliminable. Intentions may be unformed, interaction may alter states, and categories may obscure experience as well as omit it.

### Challenge 2: how can an anomaly establish deeper understanding?

It proves a failed expectation, not an explanation. An account that always invents a deeper reason afterward risks becoming unfalsifiable.

**Provisional response:** propose several explanations and low-risk, reversible probes that can distinguish them. Without discriminating evidence, retain the unknown.

### Challenge 3: is there a user's “real intention”?

If intention changes, conflicts, and forms in action, seeking the user's true intention may still assume a fixed core.

**Provisional response:** alignment here means reducing mismatch between system structure and the person's present expressions, corrections, and practical outcomes. It does not mean discovering an unchanging hidden essence.

### Challenge 4: does machine-understandable merely mean computable?

Structured fields can be processed without establishing understanding of experience.

**Provisional response:** prefer “machine-operable,” and retain human-readable explanations and correction mechanisms.

### Challenge 5: does comprehensive storage conflict with agency?

Retaining all data for future reinterpretation can create continuous surveillance and an inescapable past.

**Provisional response:** redefine it as selective storage under authorization, together with sensitivity levels, purpose limits, expiry, deletion, and forgettability.

## 7. Provisional answer

Maintain three separable kinds of data instead of seeking a completed digital self:

1. **Events:** what happened, with sources and environment.
2. **Interpretations:** how the system currently understands it, with alternatives and confidence.
3. **Structures:** how the system proposes to act, with assumptions, risks, reversibility, and confirmation points.

Every transformation returns:

~~~text
Current result + descriptive remainder + uncertainty + scope
~~~

When outcomes contradict expectations:

~~~text
Retain the anomaly
    → propose alternatives
    → generate reversible probes
    → receive user corrections
    → revise states, relationships, or categories
~~~

The representation of a person can only be:

> A temporary, local, sourced, fallible practical hypothesis that the user can revise and exceed.

## 8. Constraints on engineering

1. Store raw events separately from derived interpretations.
2. Include source, time, scope, confidence, and alternatives in state objects.
3. Explicitly support “I do not know” and “cannot determine.”
4. Let users inspect, modify, delete, and reset state models.
5. Do not turn one anomaly into a lasting personality label.
6. Use reversible, low-risk probes capable of distinguishing hypotheses.
7. Make uncertainty affect execution permissions.
8. Obtain confirmation for high-risk, irreversible actions.
9. Do not optimize structural learning only for clicks, dwell time, or immediate satisfaction.
10. Design forgettability alongside comprehensive storage.
11. Retain failed structures and rejected interpretations to avoid repeated mistakes.
12. Let every personal model be exceeded by the user.

## 9. Questions still open

1. Which aspects of remainder in the real correspond to computable uncertainty, and which do not?
2. When does an anomaly justify reverse identification rather than ordinary noise handling?
3. What evidence is sufficient to create a new state category?
4. If intervention changes the person, can feedback still validate the earlier state?
5. When explicit expression, behavioral outcomes, and long-term goals conflict, which has interpretive priority?
6. How can structural alignment with intention be measured without reducing intention to task completion?
7. How long, and in what form, should remainder be stored, and who may reinterpret it?
8. After a user deletes history, must derived preferences and strategies also be deleted?
9. When should the system offer deeper explanations, and when should it remain silent?
10. Is state the right basic unit, or are relations, processes, and transitions more fundamental?

## 10. Relationship to the design

This question constrains the [self-structuring mechanism](self-structuring.md) and [initial manifesto](initial-manifesto.md).

The engineering documents explain how the system is proposed to work. This question continues to ask what justifies its claims to understand a person, and what it must acknowledge it cannot understand.

## One-sentence version

> MirrorMind's fundamental difficulty is how a symbolic system that can never fully represent a person can still help generate meaningful action, while acknowledging failure, retaining remainder, and accepting human revision.
